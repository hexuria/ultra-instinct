# B0 / B1: Browser Use ablation (ActionTicket boundary)

Goal: measure whether an **invisible** Ultra-Instinct interceptor improves Browser Use,
without JEV and without HGRA. Weighted matcher only.

This is the keep/kill experiment from the product review. Old A1–A8 rows in
the old results tables are **historical** (different planner wiring,
pre-ticket `act`, stale tip). Do not cite them as proof of the firewall.

## Arms

| Arm | Wiring | LLM sees Ultra-Instinct? |
|---|---|---|
| **B0** | Browser Use alone (same as historical A1) | No |
| **B1** | Browser Use proposes a click → Ultra-Instinct `guard` issues an `ActionTicket` → harness `revalidate` + CDP click of the **exact** target | **No** (interceptor is harness-side) |

B2 (post-click `verify(ticket, expectation)`) is next; not in this stub.

## Stub vs full interceptor

`b01_stub.py` is a **press-path stub**, not a full Browser Use monkeypatch yet:

- **B0**: shells out to `a1_browser_use.py` with the same harness spec (needs Luna keys).
- **B1-smoke**: no LLM. For a fixed press label on a live CDP tab (or fixture),
  calls Ultra-Instinct MCP `guard` (Weighted), reads the Allow `ticket`, re-observes,
  refuses if world fingerprints would fail, then harness CDP-clicks the ticket
  target center (same pattern as `live_drive` / combo). Demonstrates the lease.
- **B1-full**: TODO — wrap Browser Use's click tool so every proposed press goes
  through guard → ticket → revalidate → click without the model knowing.
